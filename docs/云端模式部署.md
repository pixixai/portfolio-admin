# 本地与云端双模式部署

## 1. 两种运行方式

| 项目 | 本地模式 | 云端模式 |
| --- | --- | --- |
| 启动 | 双击「启动后台.cmd」，或 `npm start` | `npm run start:cloud`，正式使用建议常驻服务 |
| 管理入口 | 本机地址，免登录 | 配置的后台HTTPS域名，需管理员登录 |
| 作品入口 | 本机 `/site/`，发布后再部署 | 配置的作品域名，发布后直接更新 |
| 数据 | 默认项目 `user/` | 明确配置的独立用户目录 |
| 分享空间 | 部署时配置访问服务 | 已内置访问服务，规则随发布更新 |

- 共用一套代码，默认本地模式。「启动后台.cmd」明确使用 `--local`，不加载云端配置文件。
- 两边各自保存数据，不自动同步，通过「备份数据／恢复数据」迁移。
- 云端需要同机Nginx提供HTTPS并转发Node.js。程序仍只监听本机地址，不能当成静态HTML项目运行。
- 适用于完整Linux服务器，如阿里云轻量服务器＋宝塔；换用同类服务器主要更换配置。

## 2. 准备域名与程序

1. 准备后台和作品两个不同的域名，例如 `admin.example.com`、`example.com`。
   - 可以使用同一注册域名下的两个地址，不必再购买一个域名。
   - 两者必须使用不同主机名，不能仅端口不同。
2. 将程序放到服务器，例如 `/opt/portfolio-admin`。已有网站先保留配置和内容备份，验证新方式后再切换。
3. 安装Node.js 24（最低22.13），在程序目录安装依赖、构建编辑器：

   ```sh
   npm ci
   npm run build:editor
   ```

   - 构建需要开发依赖，不要在构建前省略它们。
   - 后台使用SQLite，不需要额外安装MySQL。
4. 在宝塔分别创建两个HTTPS站点，完成DNS和证书配置。
   - 其他别名如 `www` 可跳转到配置的主地址，不直接转发未配置域名。
   - 已有网站的公网开站条件沿用原部署流程。

## 3. 创建私有配置

1. 在服务器程序目录运行 `npm run configure:cloud`。
2. 按向导输入后台HTTPS地址、作品HTTPS地址、管理员名称、用户数据绝对目录和内部端口。
   - 地址只填协议与域名，不附加 `/site/`、`/space/` 等路径。
   - 数据目录建议 `/var/lib/portfolio-admin/user`，不能使用程序根目录、其上级或公开文件目录。
   - 默认内部端口4180，修改时同步修改Nginx代理端口。
3. 输入两次管理员密码。
   - 长度12～128个字符，输入不显示，与分享空间的4位访问码独立。
   - 向导生成 `.env.cloud`，只保存不可逆密码校验值，不保存明文密码。
   - 此文件和临时文件已被Git忽略；`.env.example`仅说明字段，不包含可用密码。
4. 创建数据目录并配置权限。
   - 以宝塔 `www` 用户为例，授予它 `/var/lib/portfolio-admin` 的写入权限，供用户目录、恢复切换和备份暂存使用。
   - 源码和依赖允许运行账户读取；`.env.cloud`由运行账户持有，权限600，用户目录上级权限750。
   - 不把源码、用户目录或配置放进可直接下载的静态站目录。

## 4. 配置常驻服务

1. 打开 [服务模板](../deploy/cloud/portfolio-admin.service)。
2. 将程序路径、Node路径、运行账户及 `ReadWritePaths` 改为实际值。
   - 用 `command -v node`确认Node的绝对路径。
   - 数据位于 `/var/lib/portfolio-admin/user` 时，`ReadWritePaths`需包含上级 `/var/lib/portfolio-admin`。
   - Node和程序路径需允许运行账户读取，不使用只能由root访问的个人目录。
3. 将模板安装为 `/etc/systemd/system/portfolio-admin.service`，由服务器管理员加载并启用此服务。
   - 依次使用 `systemctl daemon-reload`、`systemctl enable --now portfolio-admin`。
   - 用 `systemctl status portfolio-admin --no-pager`检查状态，用 `journalctl -u portfolio-admin -n 80 --no-pager`查看日志。
4. 确认服务已启动。
   - 配置缺失时启动失败，不会退回免登录的公开后台。
   - 云端不自动打开服务器浏览器。
   - 临时检查可用 `npm run start:cloud`；不要与常驻服务重复占用同一端口。

## 5. 配置两个站点的Nginx代理

1. 打开 [Nginx规则模板](../deploy/cloud/nginx-location.conf.example)。
2. 在后台和作品两个HTTPS站点中分别应用规则，保留各自域名、证书等配置。
   - 替换已有 `location /`，不重复添加；证书验证规则已有时合并。
   - 将模板中的 `CHANGE_ME_SITE_ROOT`分别改成两站实际目录。
3. 确认两站均转发到 `http://127.0.0.1:4180`，Nginx覆盖Host、真实IP和协议头。
   - 程序按已配置的Host区分后台和作品，不采用客户端传来的转发域名。
   - 代理信任仅限同机；伪造HTTPS头的非本机连接不会通过。
   - 模板关闭请求缓冲并允许最大50GB请求，实际备份仍遵守后台限制。
4. 检查配置，通过后重载Nginx。
   - 对外使用HTTPS入口，不开放内部4180端口。
   - 所有作品文件经过当前发布清单验证，不添加绕过程序、直接读取旧发布文件的规则。
   - 云端模式已内置分享空间服务，无需另外部署4181服务。旧方式切换前先验证新站，保留旧配置供恢复。

## 6. 登录、恢复与发布

1. 通过后台域名登录。
   - 管理页面、素材原件、预览、历史、导出和备份均需管理员登录。
   - 「退出登录」先走已有保存／离开流程，再清除当前会话。
2. 点击「恢复数据」，上传本地通过「备份数据」生成的完整ZIP，选择恢复类别。
   - 作品、标签、空间、访问码、排除记录、素材、设置和历史沿用现有恢复功能。
   - 恢复不替换云端管理员密码、域名和运行目录；分享地址使用当前配置的作品域名。
   - 备份可在本地与云端双向恢复，不携带管理员凭据、登录Cookie或 `.env.cloud`。
   - 恢复包含已发布内容或历史时，会同步启用恢复的展示状态；日常草稿修改仍需主动发布。
3. 用「实时预览」检查草稿和空间范围。
   - 预览在后台域名提供，要求管理员登录；私密空间还验证空间访问码。
   - 管理员登录不代替访客的空间访问码。
4. 点击「发布」，选择正文与设置，确认发布。
   - 生成成功才切换作品站版本，失败保留上一版，无需SSH连接自身或再次上传部署ZIP。
   - 空间规则随发布更新，未发布草稿不提供给访客。
   - 云端隐藏远程部署配置，仍可下载部署包用于其他用途。
5. 用作品域名及未登录浏览器检查。
   - 作品域名不能打开后台接口、素材库原始路径、预览、用户目录或配置。
   - 私密空间及其中原文件需要空间访问码；公开空间不要求管理员登录。
   - 发布记录中的「恢复此版本」也直接切换当前作品站。

## 7. 更新与修改密码

1. 更新前下载完整用户备份。
2. 停止后台服务，在程序目录更新代码、安装依赖并重新构建，再启动服务。
   - 使用 `git pull --ff-only`、`npm ci`和 `npm run build:editor`。
   - 保留 `.env.cloud`和独立用户目录，普通更新不需要恢复数据。
3. 如需改密码或忘记密码，运行 `npm run configure:cloud -- --force`。
   - 向导默认保留原域名、目录、管理员名称和端口，核对后设置新密码。
   - 核对 `.env.cloud`仍由运行账户持有且权限600，再重启后台服务。
   - 重启清除管理员会话，但保留作品资料和空间访问码。
4. 日常登录最长8小时，退出或重启需重新登录，错误尝试有次数限制。
   - 会话过期时，打开的编辑页提示在新标签页重新登录，以便继续保存当前内容。

配置参考：[宝塔反向代理](https://docs.bt.cn/user-guide/site/php/site-config/reverse-proxy)。登录使用随机会话Cookie、HTTPS、来源校验及错误次数限制，参考[OWASP登录建议](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)和[会话管理建议](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。
