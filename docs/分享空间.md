# 分享空间操作与部署

## 1. 页面布局与空间切换

本文的“本机发布后再部署、首次安装访问服务”用于本地模式。云端模式已内置分享空间访问服务，发布后直接更新作品网站，域名由云端配置管理，无需另装4181服务，见[云端模式部署](云端模式部署.md)。

1. 关闭原启动窗口，重新运行「启动后台.cmd」，刷新后台，点击左侧「分享空间」。
   - 页面保留紧凑标题，移除常驻的概括性说明；作品管理、素材库、展示设置及发布记录采用相同标题形式。
2. 在一级空间选项卡中切换「主站」或自定义空间。
   - 一级为文字导航，当前空间加粗并显示下划线，一次只选一个；下划线比空间名称略宽，左右各延长约6px，以名称居中，不包含右侧作品数量。
   - 「主站」对应根地址，例如 `https://pixixai.com/`，固定公开，不能删除或改名。
3. 在二级「包含标签」中多选作品标签。
   - 二级为小标签按钮，选中后浅色填充并显示勾号；不是切换到另一个空间。
   - 只为选中的标签生成下方作品列。空标签也可选中，之后添加作品会自动包含。
   - 标签较多时换行，作品列超出宽度时横向滚动。
   - 「包含标签」旁的提示按钮说明自动包含与排除规则。
4. 在下方工具栏设置当前空间的启用状态、公开／访问码访问、访问码及复制链接。
   - 未选标签时显示「请选择标签，添加此空间的作品」。
   - 列标题只显示标签名称和包含数量，不再提供逐列自动添加开关。

## 2. 创建、改名与删除空间

1. 点击一级选项卡末尾「＋」，输入名称，点击对号、回车或空白处完成名称输入。
2. 在创建窗口选择访问方式。
   - 「公开分享」无需访问码。
   - 「访问码访问」使用4位数字，支持 `0123` 等开头带0的号码。
3. 确认「复制主站标签」，点击「创建空间」。
   - 默认勾选，只复制当前主站包含的标签，不复制其作品排除记录。
   - 后续主站标签变化不会同步覆盖当前空间。
   - 已有空间也可点击工具栏无底框的彩色文字「复制主站标签」，使用主站当前的标签选择；悬浮变色并显示下划线，当前空间的作品排除记录保留。
4. 双击自定义空间名称可行内改名，对号、回车或失焦保存；悬浮名称旁的删除按钮可删除。
   - 删除或关闭空间不改变其他空间的标签及作品选择。
   - 关闭空间保留其配置与归属，但访客不能访问；删除空间会在下次发布、部署后移除线上入口。

## 3. 标签自动包含与作品排除

1. 在「作品管理」或「编辑作品」中维护作品标签。
   - 空间选中某标签后，默认包含该标签下的全部作品。
   - 新作品添加到此标签，会自动进入使用此标签的所有空间，无需再逐件加入。
   - 草稿可在本机实时预览；正式分享页只展示已发布的内容。
2. 在分享空间的作品列中，取消某件作品的勾选，将它从当前空间排除。
   - 排除以当前空间中的整件作品为单位。同一作品出现在多个已选标签列时，所有列同步取消。
   - 被排除的作品在后台保留为灰色、未勾选，显示「已从此空间排除」；访客页面及详情、原文件均不再提供。
   - 其他空间不受影响，包括主站；想让某作品完全不公开，需要检查所有公开入口。
3. 重新勾选灰色作品，恢复它在当前空间的展示。
   - 排除持续保留，修改作品标签或取消后再选回标签不会自动恢复。
   - 恢复后按当前空间选中的标签展示；不会带出未选标签。
4. 点击作品行右侧编辑按钮，可打开正文和标签编辑。
   - 标签决定作品在哪些列出现；作品不再通过拖到另一列改变空间分组。
   - 取消二级标签会移除整列，但保留空间的作品排除记录，方便之后重新选择。
5. 等待自动保存，或在保存失败时点击「重试保存／放弃更改」。
   - 快速连续勾选合并保存；失败保留当前选择。
   - 切换空间、编辑、预览、备份和发布会等待待保存的选择完成。

## 4. 编辑作品右侧的空间归属

1. 打开「编辑作品」，在右侧「所属分享空间」查看当前归属。
   - 只显示当前作品实际包含的空间，不罗列未加入的空间，也没有添加空间的复选框。
   - 某标签被空间选中，但当前作品已被该空间排除时，不显示此空间。
   - 主站采用相同规则；已关闭但保留归属的空间显示「已关闭」。
2. 在作品标签菜单中添加或取消标签，右侧归属即时更新。
   - 归属只读，由标签选择和作品排除规则计算，不再保留「同时加入展示空间」快捷按钮。
   - 没有归属时提示「暂未加入任何分享空间」。
3. 点击右侧带颜色的「管理分享空间」文字，保存当前作品后进入对应空间，并按作品名称筛选。
   - 入口无按钮底框，悬浮时文字变色并显示下划线，可用键盘聚焦。
   - 在空间页面选择标签、排除或恢复作品。
   - 空间中只显示已选标签的列；需要管理其他标签时，先在二级标签中选中。

## 5. 预览、访问方式和发布分享

1. 展开右侧「实时预览」，选择主站或某个空间。
   - 在空间页面切换一级选项卡时，预览跟随当前空间；二级标签和作品排除修改后自动刷新。
   - 分享页只显示当前空间中有可展示作品的标签，封面及详情也使用这些标签；「全部作品」按作品去重。
   - 私密空间首次输入访问码，普通预览刷新保留同一空间授权；不同空间独立验证。
2. 在工具栏使用「访问码」开关，样式与「启用此空间」一致。
   - 开启：空间需要访问码，后面的号码可双击编辑；关闭：空间公开访问，号码保留但置灰不可编辑。
   - 开启时单击号码不会编辑；双击，或聚焦后按Enter／F2，进入行内编辑。无需先将空间改为公开才能修改号码。
   - 尚无号码时，开启操作会先展开行内设置，提示「设置后开启」。保存4位数字后开关才真正开启；取消或非法输入不会创建没有访问码的私密状态。
   - 对号、回车或失焦保存，Esc取消，清空保留原码；非法输入或保存失败保留编辑状态，可重试。
   - 旧码在主动修改前仍可使用；旧版只有不可逆校验值时，需设置新码才能显示原文。
3. 在「发布→服务器设置」填写网站地址，例如 `https://pixixai.com`，点击「保存设置」。
   - 只填网址开头，不附加 `/space/` 等路径。留空时复制的是本机地址，无法分享给外部访客。
4. 点击「发布」，选择要更新正文的作品，确认发布，再部署到服务器。
   - 可只发布标签选择、排除记录及空间访问设置，不必重发所有正文。
   - 未勾选作品的已发布正文保持原样；空间规则随本次发布更新。
   - 本地发布改变本机 `/site/`，部署完成后才改变线上网站。
5. 点击空间工具栏「复制链接」，私密空间另行发送访问码。
   - 主站为 `https://pixixai.com/`，其他空间为 `https://pixixai.com/space/s-随机编号/`。
   - 链接不含访问码，也不列出其他空间。
   - 同一作品即使在公开空间可访问，其私密空间地址仍要求对应访问码。
   - 改码或切换访问方式后，旧解锁凭据失效；关闭空间后不能访问。

## 6. 首次在阿里云启用访问服务

1. 先在后台发布，在「发布→服务器设置」保存服务器目录，再下载「服务器配置与说明」。
   - 主站与公开空间可以纯静态部署；私密空间需要服务器访问服务，单独上传静态ZIP不能启用。
   - 日常本地编辑；云端仅运行作品访问服务，无需上传整个管理后台。
2. 在服务器安装Node.js 22或24 LTS，执行 `command -v node` 查看实际路径。
3. 将配置包 `portfolio-spaces.service` 中 `ExecStart` 的 `/usr/bin/node` 改为实际绝对路径。
   - 服务使用宝塔的 `www` 账户。默认仅监听服务器本机4181端口，不在防火墙开放4181。
   - 私密数据在网站根目录同级 `.portfolio-spaces/<站点编号>/` 中，不得移入公开网站目录。
4. 使用「部署已发布网站」上传站点与访问服务数据。
   - 部署事务需要服务器Python3。root上传时自动设置私密目录组为www、目录750、文件640；其他上传账户需管理员配置读取权限。
5. 将服务配置上传到 `/etc/systemd/system/portfolio-spaces.service`，在终端依次执行：

   ```sh
   systemctl daemon-reload
   systemctl enable --now portfolio-spaces
   systemctl status portfolio-spaces --no-pager
   ```

6. 在宝塔「网站→对应站点→设置→配置文件」先备份，将下载的 `nginx-location.conf` 放入该站点 `server { ... }` 中。
   - 已有 `location /` 时替换，不重复添加；使用 `location ^~ /` 代理整个网站，媒体扩展名规则不能绕过访问服务。
   - 证书验证目录专用规则已有同名location时合并。公开健康检查接口返回404。
   - 请求按当前发布清单验证；磁盘上的旧文件不会因为仍存在就被公开访问。
7. 检查Nginx配置，通过后重载，并完成HTTPS设置。
   - 若返回502，先检查第5步服务是否正常及Node路径是否正确。
   - ICP尚未通过时继续保持公网入口关闭，按原部署文档等待开站。
8. 用未解锁浏览器或手机核对：
   - 主站和公开空间只展示各自所选标签中的已发布作品，已排除作品不可访问。
   - 私密链接先要求访问码，输入正确后仅打开当前空间允许的作品及原文件，排除的作品仍不可访问。
   - 空间甲的权限不能打开空间乙独有的内容；不在主站的作品不能通过主站详情地址访问。
9. 后续继续本地编辑→发布→部署。更新访问服务程序后执行 `systemctl restart portfolio-spaces`。
   - 仅更新作品及空间数据无需重启云端服务；从旧版升级本次空间访问逻辑时，需部署新程序并重启。
   - 浏览器解锁最长8小时；退出私密空间清除本空间凭据，重启服务清除已有解锁状态。

## 7. 备份、恢复与升级兼容

1. 点击「备份数据」，勾选「作品」。
   - 保存主站及所有分享空间的标签规则、作品排除记录、访问方式、访问码和作品草稿／发布内容。
   - 完整迁移可同时选择设置、素材库、发布历史和后台偏好。
   - 后台显示访问码所需密文和密钥随私人备份保存，不写入云端访问清单；备份请存放在私人位置。
2. 在新后台点击「恢复数据」，上传备份，选择需要恢复的类别。
   - 标签自动包含规则、排除记录及访问码按备份恢复，已排除作品不会自动重新展示。
   - 旧版逐件选择迁移时保留现有作品范围，后续新增作品自动跟随已选标签；旧按列选择差异保留兼容。
   - 重新选择某标签会使用该标签的完整自动包含规则，空间中已明确排除的作品仍保持排除。
   - 升级不改写已发布网页或历史文件，需主动发布并部署后应用到线上。
3. 需要纯静态托管时，在「发布记录→部署包」选择通用、腾讯或ESA。
   - 静态ZIP包含主站及已启用公开空间的网页，排除的作品不会写入对应空间；不包含私密页面、校验数据或访问服务。
   - 部署包的恢复描述以主站已发布作品为范围，不包含完整空间规则、私密作品及全部草稿；恢复完整项目使用用户备份。

访问码页面保持严格同源验证。已被访客合法保存的文件，后续排除也无法从对方设备收回。
