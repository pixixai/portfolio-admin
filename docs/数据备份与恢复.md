# 数据备份与恢复

右上角的数据操作统一为「备份数据」「恢复数据」「发布」。旧的「导入项目」入口已合并到「恢复数据」，「发布与导出」改名为「发布」，网站部署包仍在发布流程中下载。

## 1. 备份数据

1. 点击右上角「备份数据」。当前编辑中的作品和网站设置会先保存为草稿。
2. 勾选需要备份的数据，默认全部勾选。

   | 类别 | 包含内容 |
   | --- | --- |
   | 网站设置 | 已保存与已发布的设置：首页背景、蒙板颜色与不透明度、姓名、联系方式、页脚等 |
   | 作品 | 草稿、已发布内容、回收站、标签、排序、封面比例与取景，以及主站选择、各分享空间的标签自动包含规则与作品排除记录、公开／私密状态、访问码校验数据和供后台显示访问码的本地密文及密钥 |
   | 素材库 | 全部原始素材、未使用素材、文件夹、空文件夹及素材排序 |
   | 发布历史 | 仍保留的历史版本及当前发布状态，同时包含关联作品和网站设置 |
   | 后台偏好 | 历史保留数量、导出平台、SSH连接地址及指纹等非敏感配置 |

   - 所选作品、网站设置或历史版本依赖的素材会自动加入，不需要另行勾选「素材库」。勾选「素材库」还会带上未使用素材和空文件夹。
   - 勾选「发布历史」会同时勾选「作品」和「网站设置」；取消其中任意一项时会同时取消发布历史。
   - 用户数据备份不包含程序代码、依赖、临时预览、失败构建缓存、SSH密码或私钥。
3. 点击「备份并下载」，等待校验完成，浏览器会下载`portfolio-user-backup-日期.zip`。
   - 如果浏览器没有自动开始下载，可点击面板中的下载链接。
   - 备份文件含有未公开草稿和原始素材，应保存在自己的电脑或私人备份位置，不要放到网站公开目录。
   - 包含作品的新版备份也能还原后台显示的访问码，包括开头带0的四位数字码。旧备份仅有不可逆校验值时，恢复后原码仍可验证，但需设置新的四位数字码才能在后台显示。旧码不自动截短。显示密文和密钥不随网站发布。
   - 备份采用流式ZIP，不需要把所有媒体一次读入内存；当前包大小及展开总量各限50 GB，媒体仍遵守单张图片30 MB、音视频200 MB的限制。特别大的资料可分类别备份。

## 2. 恢复数据

1. 点击「恢复数据」→「选择备份文件」，选取之前下载的ZIP。
2. 等待上传和检查完成，查看备份名称、作品数量、素材、文件夹和历史记录数量。
3. 勾选本次需要恢复的数据类别。
   - 只能选择该包实际包含的类别。可以从完整备份中只恢复网站设置，也可以只恢复素材库或后台偏好。
   - 用户备份采用替换所选类别的方式，未选择的类别保留；所选作品会恢复其草稿、发布状态和回收站状态。
   - 仅恢复网站设置不会替换作品；仅恢复素材库不会替换作品和网站设置，也不会改动当前发布版本。
   - 如果现有未恢复的作品、网站设置或历史版本仍引用某些素材，这些素材会保留，不会被素材库恢复误删。
   - 历史版本会根据备份内容和当前版本的展示模板重建，不执行备份中携带的网页脚本。
4. 核对覆盖提示，点击「恢复所选数据」，等待完成。
   - 后台先生成和校验恢复副本，再启用新数据。恢复期间暂时禁止编辑、预览、发布和部署，避免并发写入。
   - 检查备份之后如果已有数据发生变化，需要重新选择文件并确认。
   - 恢复失败时保留或恢复原数据；切换过程意外中断时，下次启动会先恢复未完成操作，不会误初始化一份默认数据。
5. 成功后回到作品管理，检查所选数据。当前本地后台恢复不会直接更新阿里云网站，需要再走正常发布／部署流程。
   - 草稿按备份恢复主站及各分享空间的标签规则与排除记录，已排除作品不会自动恢复。旧版逐件选择保留现有作品范围并迁为标签自动包含，之后新增作品按标签跟随；恢复的已发布内容及历史记录保持原有状态，直到下次主动发布。

## 3. 兼容恢复网站部署包

1. 在「恢复数据」选择新版后台导出的网站部署ZIP；腾讯、通用静态网站和带`public/`目录的ESA包均可识别。
2. 查看「网站部署包」提示，并选择其中的作品、设置或素材。
3. 点击「恢复所选数据」。

   - 部署包只包含该版本已发布的内容。兼容恢复将作品和设置恢复为草稿，同编号作品的草稿会被替换；其他作品、当前发布内容及历史记录保留。
   - 部署包恢复描述以主站已发布内容为范围，不包含完整分享空间配置、私密作品、未发布草稿、所有未使用素材、空文件夹或全部历史，不能代替用户数据备份。
   - 没有`portfolio-restore.json`恢复描述的旧网页ZIP无法恢复。网页“另存为”的文件也不能代替部署包。

## 4. 更新后台与换服务器

当前版本仅允许本机访问。将后台适配为可通过域名登录的云端管理系统后，可以继续沿用本节的备份与恢复流程；只部署作品网站时，网站没有恢复后台数据的入口。

### 正常更新后台

1. 点击「备份数据」，备份全部数据并下载到自己电脑。
2. 停止后台，更新程序文件并安装对应依赖，保留现有`user`数据目录。
3. 重启后台，直接继续使用原数据，不需要再导入。

### 全新部署或更换电脑／服务器

1. 在新环境部署并启动后台程序。
2. 点击「恢复数据」，上传用户备份ZIP，通常勾选全部类别。
3. 完成恢复后检查作品、设置和素材，再发布网站。

## 5. 临时文件与恢复前副本

- 备份准备和上传检查使用`user`同级的`.portfolio-user-transfer-站点标识/`，不放入正式用户目录，避免复制整个`user`时又带上备份缓存。未完成的临时文件在一小时后于后续备份操作中清理；恢复成功后清理对应暂存数据。
- 恢复成功后，恢复前的完整用户目录保留在同级`.portfolio-user-before-restore-时间-标识/`。这是额外的安全副本，确认恢复正确且已有可用本地备份后，可自行移除不再需要的旧副本，保留正在使用的`user`。
- 恢复需要可用磁盘空间；历史版本较多时，校验和重建时间也会增加。
- 用户数据目录、传输缓存、恢复副本和切换记录均不提交GitHub。普通代码更新不应删除这些私人数据。
